# Remaining work for source, tissue interaction, and detector

This document summarizes the remaining work identified by comparing the
current `ti_new` implementation with the General project documents:

- `General/PRD.md`
- `General/TRD.md`
- `General/SYSTEM_DATASHEET.md`
- `Source_team_setup/README.md`
- `Detector_team_setup/README.md`

## Already implemented

- Per-view rotating source/detector geometry from `ct_system_output.json`.
- 16,728-view trajectory.
- 64 x 888 = 56,832 rays per view.
- Polychromatic analytical spectrum.
- Fan/cone-beam ray generation.
- Voxel traversal through the cylindrical phantom.
- Energy-dependent Beer-Lambert attenuation.
- Material attenuation through `xraylib`.
- Energy-resolved tissue output.
- Energy-integrating detector response.
- Detector efficiency, blur, gain variation, dead pixels, and noise.
- Negative detector signal clamping.
- Per-view CSV and NPY output.
- Units, dimensions, dependency, and change documentation.

## Remaining work

### 1. Complete the X-ray source model

The current source model is simplified. It should implement:

- Photon-energy sampling into explicit `photon_energies`.
- Focal-spot sampling using the configured focal-spot size.
- Per-photon weights based on:

  ```text
  mA x exposure_time / number_of_photons
  ```

- Source intensity scaling using `tube_current_ma`, `exposure_time_s`, and
  `total_mas`.
- Explicit use of the configured bowtie filter.
- Optional heel-effect modeling.
- Validation of sampled energies against the spectrum.
- Validation that sampled directions remain inside the configured cone angle.

Currently, `photons_per_ray` is a manual calibration parameter rather than a
complete physical source-photon model.

### 2. Calibrate the source spectrum

The current spectrum has the expected analytical shape but is not an absolute
photon fluence.

The project still needs:

- A reference photon fluence or air-scan calibration.
- A documented conversion from mA-s to photons.
- Calibration validation against a known open-beam exposure.
- Consistent source units passed into tissue interaction.

Until this is done, detector electron values are simulation-scale values and
not clinically calibrated values.

### 3. Add real phantom loading

The current tissue stage uses the dummy cylinder phantom.

Still required:

- Load the professor-provided real voxel dataset.
- Confirm its axis ordering.
- Confirm voxel spacing in all three dimensions.
- Confirm material-ID mapping.
- Support non-cubic voxels if necessary.
- Validate phantom bounds against the CT geometry.

The current placeholder is:

```text
voxel_material.shape = (ny, nz, nx)
voxel_size_mm = 1.0
```

### 4. Improve tissue-interaction physics

The current phase contains Beer-Lambert primary attenuation only.

Planned extensions include:

- Photoelectric interaction modeling.
- Compton scattering.
- Rayleigh scattering.
- Monte Carlo photon transport.
- Scattered-photon contribution to detector fluence.
- Photon-fate tracking: transmitted, absorbed, and scattered.
- Beam-hardening validation using polychromatic attenuation.

The API currently reserves:

```python
scatter_model="monte_carlo"
```

but does not implement it yet.

### 5. Improve tissue performance

The current tissue loop processes rays one by one. For
`16,728` views x `56,832` rays per view, this will be slow.

Remaining performance work includes:

- Vectorized ray traversal where possible.
- Caching attenuation tables.
- Reusing geometry between compatible views.
- Parallel processing by view or ray block.
- Chunked processing to limit memory usage.
- Avoiding repeated CSV writes if a binary handoff is sufficient.
- Progress reporting and resumable processing.

Running every view creates approximately:

```text
16,728 CSV files
16,728 NPY files
```

The total detector-pixel row count is approximately:

```text
16,728 x 56,832 = 950,685,696 detector-pixel rows
```

Storage and runtime should therefore be measured before a full production run.

### 6. Validate tissue-interaction acceptance criteria

The General documents require validation of:

- No negative path lengths.
- Correct ray count per view.
- Correct detector image shape.
- Monotonic transmission decrease with increasing tissue path length.
- Correct energy dependence of attenuation.
- Correct behavior for air-only, tissue-only, and mixed-material rays.
- Correct handling of rays that miss the phantom.
- No NaN or infinite values.

Some basic checks exist, but a formal automated validation suite is still
needed.

### 7. Complete detector calibration output

The detector physics is present, but the official detector handoff is not yet
fully generated by `ti_new`.

The detector documentation expects:

```text
detector_handoff_package.npz
detector_handoff_package_metadata.json
```

with:

- Measured detector signal.
- Reference/open-beam signal.
- Gain map.
- Dead-pixel map.
- Projection angles.
- Energy-bin metadata.
- Detector configuration.
- Normalization convention.

The current implementation writes per-view CSV and NPY files, but does not yet
assemble this complete handoff package.

### 8. Add open-beam/reference detector calibration

For reconstruction, the detector needs a reference signal:

```text
line_integral = -ln(measured_signal / reference_signal)
```

Still required:

- Generate an air/open-beam scan with no phantom.
- Run it through the same detector model.
- Store `reference_signal_electrons`.
- Protect the logarithm from zero values.
- Handle dead pixels and clamped signals.
- Generate normalized projection data.

### 9. Resolve negative-signal handling for reconstruction

The clamp is useful because physical electrons cannot be negative:

```python
measured_signal = np.maximum(measured_signal, 0.0)
```

However, reconstruction requires positive values for:

```text
-ln(measured_signal / reference_signal)
```

A small positive floor may also be required:

```text
measured_signal_safe = max(measured_signal, epsilon)
```

Otherwise, zero-clamped pixels can produce undefined logarithms.

### 10. Add a complete multi-view detector handoff

The current output is one file per view. Reconstruction will eventually need
a consolidated structure such as:

```text
measured_signal_electrons
shape = (total_views, detector_rows, detector_channels)
```

and:

```text
angles_deg
shape = (total_views,)
```

The detector-stage data must be assembled from all `16,728` views into an
`.npz` package or equivalent format.

## Highest-priority remaining work

For completion of only the source, tissue-interaction, and detector modules,
prioritize:

1. Implement the full source photon model: energy sampling, focal spot, mA,
   exposure time, and photon weights.
2. Calibrate the source spectrum to absolute photons.
3. Add automated validation tests.
4. Generate open-beam/reference detector data.
5. Produce the official detector handoff package.
6. Add real phantom loading when the final voxel data is available.
7. Optimize full 16,728-view execution.
8. Add Monte Carlo scattering if required by the phase-1 scope.

The basic source-to-tissue-to-detector cascade is working, but source
calibration, formal validation, open-beam normalization, official detector
handoff, real-phantom support, and full-scale performance remain before the
three-module implementation can be considered complete according to the
General project documents.
